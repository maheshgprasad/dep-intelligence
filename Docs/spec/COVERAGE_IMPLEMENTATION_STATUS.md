# Test Coverage Implementation Status

## Overview

The test coverage feature in the Dependency Intelligence Dashboard currently provides **mock/simulated data** for most languages. Real test coverage analysis is only partially implemented for Node.js/JavaScript projects.

## Language Detection - Single Source of Truth

**Important**: Test coverage now uses the same language detection as "Monitored Repositories" to ensure consistency across the dashboard.

- **Primary Source**: [`language_detection.json`](output/language_detection.json) generated by the `detect_language` MCP tool
- **Fallback**: Local file system detection if `language_detection.json` is not available
- **Execution Order**: The `detect_language` tool always runs BEFORE `run_coverage` to ensure language data is available

This ensures that the language shown in "Test Coverage" matches exactly what's shown in "Monitored Repositories".

## Implementation Status by Language

### ✅ Fully Implemented

#### Python
- **Status**: Real coverage implementation
- **Tool**: `pytest --cov --cov-report=json`
- **Requirements**:
  - Python 3.x installed
  - pytest and pytest-cov packages installed (`pip install pytest pytest-cov`)
  - Tests configured in the repository
- **Behavior**:
  - Automatically clones repository if not available locally
  - Runs pytest with coverage
  - Parses coverage.json output
  - Falls back to mock data if pytest not available or tests fail
- **Success Message**: "✅ Real coverage data from pytest"
- **Fallback Message**: "⚠️ Mock data - pytest not configured or tests failed"

#### Go
- **Status**: Real coverage implementation
- **Tool**: `go test -coverprofile=coverage.out -covermode=count ./...`
- **Requirements**:
  - Go installed
  - Tests configured in the repository (files ending in `_test.go`)
- **Behavior**:
  - Automatically clones repository if not available locally
  - Runs go test with coverage profile
  - Parses coverage.out output
  - Falls back to mock data if go not available or tests fail
- **Success Message**: "✅ Real coverage data from go test"
- **Fallback Message**: "⚠️ Mock data - go test not configured or tests failed"

## Real vs Mock Coverage Data

### Real Coverage (Python & Go)
When real coverage is successfully generated:
- **Actual file paths** from the repository
- **Real coverage percentages** from test execution
- **Actual uncovered line numbers**
- **Branch coverage** (Python only, if available)
- **Green success badge** in UI: "✅ Real Coverage"
- Repository is cloned to `/tmp/dep-intel-coverage/[repo-name]`

### Mock Coverage (Fallback)
When real coverage cannot be generated:
- Creates 5-12 files per repository
- Uses language-appropriate file patterns (e.g., `.go` for Go, `.py` for Python)
- Generates realistic coverage percentages (60-95% range)
- Includes line, statement, branch, and function coverage metrics
- Provides simulated uncovered line numbers
- **Blue/Yellow info badge** in UI explaining why mock data is shown

## How It Works

### Execution Flow

1. **Language Detection**: Reads from `language_detection.json` (single source of truth)
2. **Repository Access**:
   - Checks common local paths first
   - Clones repository if not found locally (for Python/Go)
3. **Coverage Execution**:
   - **Python**: Runs `pytest --cov=. --cov-report=json`
   - **Go**: Runs `go test -coverprofile=coverage.out -covermode=count ./...`
4. **Result Parsing**:
   - Parses tool-specific output format
   - Normalizes to common coverage schema
5. **Fallback**: Uses mock data if real coverage fails

### Requirements for Real Coverage

**Python Repositories:**
```bash
# Install dependencies
pip install pytest pytest-cov

# Repository must have tests
# Example: test_*.py or *_test.py files
```

**Go Repositories:**
```bash
# Go must be installed
go version

# Repository must have tests
# Example: *_test.go files
```
